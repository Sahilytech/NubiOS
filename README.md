# NubiOS

> Proprietary, local-first AI desktop assistant for Windows, created by Sarah Lee Olivera.

NubiOS is designed as a real desktop software product rather than a chatbot wrapper. Its core is useful offline and keeps automation behind explicit application, filesystem, and permission boundaries.

## Product status

### Stable
- PySide6 desktop shell with Dashboard, Chat, Tasks, Memory, Automation, Plugins, and Settings views
- Deterministic intent parsing for common desktop commands
- SQLite persistence for conversations, tasks, memories, preferences, and audit records
- Centralized permission manager
- Bounded filesystem search and path validation
- Configurable application launching without shell interpolation
- Structured local JSONL audit logging
- Offline mock AI mode
- Provider abstraction with optional Ollama adapter
- Optional Whisper/faster-whisper adapter
- Plugin manifest discovery with declared permissions
- Automated tests and Windows PyInstaller build flow

### Experimental
- Ollama local inference
- Plugin runtime execution (manifest discovery is implemented; sandboxed execution is not)
- Vision provider integration
- Web provider integration

### Planned
- Sandboxed plugin execution
- Semantic/vector memory search
- Full voice capture and TTS UX
- Installer and signed release pipeline
- Expanded Windows application discovery

## Architecture

```text
User
  |
UI / Voice
  |
Assistant
  |
Intent Engine -----> AI Provider (optional)
  |
Permission Manager
  |
Action / Service
  |
SQLite + local audit log
```

AI providers never receive unrestricted operating-system access. Basic commands are deterministic first; actions are explicit and permission-gated.

## Quick start

Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:NUBIOS_MOCK_AI="true"
python -m nubios.main
```

Development install:

```powershell
pip install -e ".[dev]"
pytest
```

## Configuration

Copy `.env.example` to `.env` if you want a local configuration file, and never commit it. Environment variables include:

- `NUBIOS_MOCK_AI` — offline mock mode; recommended for development and CI
- `NUBIOS_AI_PROVIDER` — `mock` or `ollama`
- `NUBIOS_AI_MODEL` — local model name
- `NUBIOS_ALLOWED_DIRECTORIES` — semicolon-separated directories NubiOS may inspect
- `NUBIOS_DATA_DIR` — local database/log location
- `NUBIOS_THEME` — UI theme preference

NubiOS does not expose the entire filesystem by default.

## Security

Security is part of the architecture, not an optional feature. NubiOS does not execute arbitrary shell commands generated by an AI model. Application launching uses argument lists with `shell=False`; filesystem access is bounded to configured directories; sensitive operations can require confirmation; plugin manifests declare permissions; and audit logs deliberately exclude common secret fields.

Screenshots and external network capabilities are opt-in boundaries. They are never silently uploaded by the core assistant.

## AI providers

The application depends on the `AIProvider` abstraction rather than a specific vendor. Mock mode requires no API key, network connection, Ollama installation, or voice model. Ollama is optional and configurable through environment variables. Cloud providers can be integrated through the same abstraction without coupling the desktop core to a commercial SDK.

## Voice and vision

Voice recognition uses an optional faster-whisper adapter. NubiOS still starts normally when the optional package is unavailable. Text-to-speech and vision expose provider boundaries; complete capture/provider integrations remain experimental.

## Plugins

Plugins begin with a manifest containing name, version, description, author, and permissions. Example permissions include `tasks.read`, `memory.read`, `filesystem.read`, `applications.launch`, `web.access`, `microphone`, and `screen.capture`. Arbitrary plugin execution is intentionally not enabled until a sandbox is implemented.

## Testing

```powershell
pytest
```

The suite is designed to run without cloud AI or external services and covers intent parsing, SQLite persistence, tasks, permissions, actions, event delivery, filesystem boundaries, plugin manifests, and configuration.

## Building Windows executable

Run `build_exe.bat` on Windows. The script installs the project, runs tests, and invokes PyInstaller. The resulting executable does not require Python or development tools on the target machine.
